# AGENTS.md

Инструкции для AI-агентов, которые работают с этим репозиторием.

## О проекте

Веб-страница с листом персонажа (Champion Sheet) настольной ролевой игры
Twilight Sword. Пользователь заполняет лист в браузере, данные сохраняются
локально.

Архитектурные решения описаны в [docs/adr](docs/adr). Перед изменениями прочитай
их; если изменение противоречит принятому ADR — сначала предложи новый ADR.

## Ограничения MVP

Подробности и обоснование — в [ADR-0001](docs/adr/0001-mvp-architecture.md).

- **Без сборки, фреймворков, npm-зависимостей и CDN.** Страница должна
  открываться двойным кликом из файловой системы.
- **Структура:** `index.html` в корне; стили в `assets/css/`, по файлу на
  назначение, стили блока — в `assets/css/blocks/`; скрипты в `assets/js/`,
  по файлу на ответственность; собственные иконки в `assets/icons/`.
- **Новый файл подключай в `index.html`.** Стили — от общих к частным, стили
  блоков последними. Скрипты — после тех, от которых они зависят.
- **CSS-переменные объявляй только в файле с переменными.** Общие цвета,
  шрифты и размеры — переменными.
- **Скрипты — обычные, не ES-модули:** модули не загружаются по `file://`.
- **Один файл — один модуль.** Скрипт объявляет одно глобальное имя по имени
  файла — объект, который возвращает сразу вызываемая функция (IIFE). Наружу
  возвращай только то, что нужно другим скриптам. Обращайся к ним через имя
  модуля.
- **Данные и хранилище не обращаются к DOM.** Код, который работает с полями
  на странице, не обращается к `localStorage`.
- **Хранение — `localStorage`.** Состояние листа — один JSON-объект под одним
  ключом, без версии формата. Сохранение при каждом изменении, восстановление
  при загрузке.
- **Адаптивная вёрстка:** на десктопе раскладка повторяет бумажный лист,
  на телефоне карточки идут в одну колонку.
- **Не добавляй без отдельного решения** то, что записано как точки роста:
  Vite + React + TypeScript, экспорт и импорт JSON, экспорт в PDF.

## Авторские права

- Не используй графику издателя игры: логотип, эмблемы, иконки состояний,
  орнаментные рамки, фоновые узоры, рисунки. Оформление — только собственное:
  CSS, текст, простые собственные иконки.
- Не добавляй в репозиторий официальный PDF листа персонажа и другие материалы
  издателя. Репозиторий публичный и распространяется под лицензией MIT.
- Названия полей и игровые термины («Сила», «Зины», «Рана») использовать можно.

## Код

- **Типы обязательны.** Укажи типы параметров и возвращаемых значений
  у каждой функции:
  - в коде страницы (`assets/js`) — в JSDoc, общие типы — через `@typedef`;
  - в тестах (`tests/`) — в синтаксисе TypeScript, общие типы — через `type`.
- **Без приведения типов:** ни `/** @type {string} */ (value)` в JavaScript,
  ни `value as string` или `value!` в TypeScript. Если значение может
  не подойти, проверь его и выбрось ошибку; для проверок пиши
  функции-сужения с `value is Type` в возвращаемом типе.
- **Словесные комментарии — только в исключительных случаях:** код можно
  понять двояко, он очень сложный или выглядит сомнительно. Комментарий
  объясняет, почему код такой.
- **В остальных случаях код понятен без слов:** понятные имена, отдельные
  функции с говорящими названиями, именованные константы вместо магических
  значений.
- Тексты интерфейса — на русском.

## Тесты

Подробности и обоснование — в [ADR-0002](docs/adr/0002-unit-tests-vitest.md).

- **Тесты — на TypeScript, код страницы — на JavaScript.** Не переводи код
  страницы на TypeScript без решения о переходе на Vite + React + TypeScript.
- **Файлы:** `tests/<модуль>.test.ts`, по файлу на модуль из `assets/js`.
- **Скрипт страницы загружай через `loadScript`** из
  `tests/helpers/load-script.ts`. Зависимости модуля передавай вторым
  аргументом.
- **Vitest не проверяет типы.** Перед тем как закончить работу, запусти
  `npm test`: он проверяет форматирование, типы и запускает тесты.

## Git

- **Ветки:** `тип/краткое-описание` латиницей в kebab-case, например
  `feat/stats-block`, `docs/adr-0002-json-export`.
- **Коммиты:** [Conventional Commits](https://www.conventionalcommits.org/)
  на английском. Заголовок в повелительном наклонении, до 72 символов, без точки
  в конце. В теле — зачем сделано изменение.
- Типы: `feat`, `fix`, `docs`, `refactor`, `style`, `test`, `chore`, `ci`.
- Не коммить, не пушь и не создавай pull request без явного подтверждения
  пользователя.

## Документация

- Документация и ADR пишутся на русском.
- Новый ADR — файл `docs/adr/NNNN-краткое-название.md` со следующим номером
  и разделами: статус, дата, контекст, решение, отклонённые варианты,
  последствия.
