# План реализации MVP

Основа — [ADR-0001](../adr/0001-mvp-architecture.md).

## Принятые решения

- **Счётчики:** «Сердца» (`hearts`) и «Выносливость» (`stamina`), у каждого
  текущее значение и максимум. Рисуем собственными фигурами — сердце и ромб
  на CSS/SVG, без графики издателя. Подписи — в `title` и `aria-label`.
- **Характеристики** — числа.
- **Пустое числовое поле** хранится как `null`.
- **Связь полей и данных листа:** у каждого поля атрибут `data-field` с путём
  в данных листа, например `stats.strength` или `inventory.items.0.slots.2`.
- **Данные растут по этапам:** каждый этап добавляет в пустые данные листа
  свою часть.
- **Версии формата данных нет:** в MVP она не нужна.
- **Проверка** — ручная, в браузере: короткая в конце каждого этапа и полный
  чек-лист в конце последнего.

## Модель данных

```
champion: name, origin, path, lineage
hearts: current, max
stamina: current, max
gift
stats: strength, agility, vitality, perception, will, knowledge, charisma, stealth
conditions: poison, stun, confusion, wound, fear, freeze, blindness, silence, burning, knockout
equipment: weapons[3]: name, type, range, damage, notes; armor: name, type, notes, value
inventory: maxSlots, items[8]: name, slots[3]; zins: green, blue, red; ingredients
traits
hope
```

## Этап 1. Каркас страницы

1.1. **Разметка.** `lang="ru"`, viewport, заголовок,
подключение стилей и скриптов с `defer`, пять пустых карточек.
Видимые заголовки — как в оригинале, только у «Снаряжения», «Инвентаря»
и «Черт и Заклинаний»; у «Чемпиона» и «Характеристик» `<h2>` скрыт
классом `visually-hidden`. Каждая карточка названа своим `<h2>` через
`aria-labelledby`.

1.2. **Базовые стили.** CSS-переменные палитры (бирюзовый, бежевый,
коричневый), шрифтов и размеров; фон и шрифт страницы; карточки и заголовки.

1.3. **Сетка.** Десктоп — раскладка как в бумажном листе
(правая колонка «Черты и заклинания» на всю высоту), узкий экран — одна
колонка.

1.4. **Данные.** Функция, которая возвращает пустые данные листа; пока это
пустой объект.

1.5. **Хранилище.** Ключ `localStorage`, загрузка и сохранение данных листа.
Если данных нет или JSON битый — пустые данные.

1.6. **Привязка полей.** Чтение и запись значения по пути, заполнение полей
с `data-field` из данных листа, чтение значения поля по его типу: текст,
число, чекбокс.

1.7. **Запуск.** Загрузить данные листа, заполнить поля, на событие `input`
обновить данные и сохранить.

1.8. **Проверка.** Страница открывается из файловой системы, в консоли нет
ошибок, сетка правильная на десктопе и на ширине 375 px.

## Этап 2. Блок «Чемпион»

2.1. **Данные.** Добавить `champion`.

2.2. **Разметка.** Поля: имя, происхождение, путь, род.

2.3. **Стили блока.** Текстовые поля в стиле линованного листа.

2.4. **Проверка.** Значения сохраняются после перезагрузки.

## Этап 3. Блок «Характеристики»

3.1. **Данные.** Добавить `hearts`, `stamina`, `gift`, `stats`,
`conditions`.

3.2. **Разметка счётчиков.** Сердца и Выносливость: текущее
значение и максимум; поле Дара.

3.3. **Разметка характеристик.** Восемь числовых полей
с подписями.

3.4. **Разметка состояний.** Десять чекбоксов с цветными
метками.

3.5. **Стили фигур.** Сердце и ромб вокруг полей счётчиков.

3.6. **Стили полей.** Числовые поля характеристик, метки
состояний.

3.7. **Проверка.** Числа и чекбоксы сохраняются; очищенное числовое поле
остаётся пустым после перезагрузки.

## Этап 4. Блок «Снаряжение»

4.1. **Данные.** Добавить `equipment`.

4.2. **Разметка оружия.** Три строки: название, тип, дальность,
урон, описание.

4.3. **Разметка доспеха.** Название, тип, описание, Броня.

4.4. **Стили блока.** Таблица оружия, щит с Броней.

4.5. **Проверка.** Все поля сохраняются; на 375 px строки оружия без горизонтальной
прокрутки.

## Этап 5. Блок «Инвентарь»

5.1. **Данные.** Добавить `inventory`.

5.2. **Разметка строк.** Максимум ячеек и восемь строк:
название и три отметки ячеек.

5.3. **Разметка зин и ингредиентов.** Три счётчика зин и поле
ингредиентов.

5.4. **Стили блока.** Ячейки-квадраты, шестиугольники зин.

5.5. **Проверка.** Отметки ячеек и зины сохраняются.

## Этап 6. Блок «Черты и заклинания»

6.1. **Данные.** Добавить `traits` и `hope`.

6.2. **Разметка.** Многострочное поле и счётчик Надежды.

6.3. **Стили блока.** Линованное многострочное поле, счётчик Надежды.

6.4. **Итоговая проверка** по чек-листу ниже.

## Итоговый чек-лист

- Страница открывается двойным кликом из файловой системы, в консоли нет ошибок.
- Все поля заполняются; после перезагрузки значения на месте.
- Чекбоксы состояний и ячеек сохраняются.
- Очистка числового поля сохраняется как пустое значение.
- Битый JSON в `localStorage` не ломает страницу — открывается пустой лист.
- Десктоп: раскладка как в бумажном листе. Ширина 375 px: одна колонка,
  без горизонтальной прокрутки.
