# ADR-0001: Архитектура MVP веб-листа персонажа

- **Статус:** принято
- **Дата:** 2026-11-04, обновлено 2026-11-06

## Контекст

Нужна веб-страница с листом персонажа (Champion Sheet) настольной ролевой игры
Twilight Sword.

Лист состоит из пяти блоков:

1. **Чемпион** — имя, происхождение, путь, род.
2. **Характеристики и состояния** — Сердца и Выносливость с максимумами, Дар;
   8 характеристик (Сила, Ловкость, Живучесть, Восприятие, Воля, Знание, Харизма,
   Скрытность); 10 состояний (Отравление, Оглушение, Замешательство, Рана, Страх,
   Заморозка, Ослепление, Немота, Горение, Нокаут).
3. **Снаряжение** — 3 строки оружия/предмета (тип, дальность, урон, описание)
   и доспех (тип, описание, Броня).
4. **Инвентарь** — максимум ячеек, 8 строк с отметкой занятых ячеек (до 3),
   зины трёх цветов (зелёные, синие, красные), ингредиенты и компоненты.
5. **Черты и заклинания** — свободный текст и счётчик Надежды.

Нужно решить, как воспроизвести внешний вид, на каком стеке делать, как
разложить код по файлам и где хранить данные.

## Решение

### Внешний вид — своя вёрстка на HTML/CSS в стиле оригинала

Лист сверстан заново: пять карточек в сетке, бирюзовые заголовки, бежевый фон,
коричневые рамки. Вёрстка адаптивная: на десктопе раскладка повторяет бумажный
лист, на телефоне карточки идут в одну колонку.

Графику оригинала не используем. Вместо неё — собственное оформление: рамки
и фон на CSS, состояния подписаны текстом и выделены цветом, при необходимости —
простые собственные иконки.

### Стек — HTML, CSS и чистый JavaScript без сборки

Без сборки, фреймворков и зависимостей. Страница открывается двойным кликом
из файловой системы и размещается на любом статическом хостинге.

### Структура файлов

```
index.html
assets/
  css/
    tokens.css
    base.css
    sheet.css
    card.css
    blocks/
      identity.css
      attributes.css
      equipment.css
      inventory.css
      traits.css
  js/
    model.js
    storage.js
    form.js
    app.js
  icons/
```

- `index.html` — разметка листа, лежит в корне.
- `assets/css/tokens.css` — только блок `:root` с CSS-переменными: цвета,
  шрифты, размеры.
- `assets/css/base.css` — сброс и стили `body`.
- `assets/css/sheet.css` — сетка листа и размещение карточек в ней.
- `assets/css/card.css` — общее оформление карточки и её заголовка.
- `assets/css/blocks/*.css` — стили содержимого одного блока; файл появляется
  вместе с блоком.
- `assets/js/model.js` — модель листа: версия схемы и пустой лист.
- `assets/js/storage.js` — загрузка и сохранение листа в `localStorage`.
- `assets/js/form.js` — связь полей формы с моделью.
- `assets/js/app.js` — запуск: загрузка листа, заполнение формы, подписка
  на ввод.
- `assets/icons/` — собственные иконки, когда они появятся.

`model.js` и `storage.js` не обращаются к DOM, `form.js` не обращается
к `localStorage`.

### Стили

`index.html` подключает стили в порядке: `tokens.css`, `base.css`, `sheet.css`,
`card.css`, затем файлы блоков в порядке карточек.

CSS-переменные объявляются только в `tokens.css`. На работу переменных порядок
`<link>` не влияет: `var()` подставляется при расчёте итоговых стилей, когда
загружены все файлы. Для обычных правил порядок важен: при одинаковой
специфичности побеждает файл, подключённый позже. Поэтому файлы блоков идут
после `card.css` и могут уточнять общее оформление карточки.

### Скрипты

Скрипты — обычные, не ES-модули: браузеры не загружают модули по `file://`.
Все подключаются с `defer` в порядке `model.js`, `storage.js`, `form.js`,
`app.js`. Скрипты с `defer` выполняются строго в порядке подключения, а
объявления верхнего уровня попадают в общую глобальную область, поэтому файл
может использовать то, что объявили файлы, подключённые раньше него.

Каждый файл имитирует модуль: объявляет одно глобальное имя по имени файла
(`model`, `storage`, `form`, `app`) — объект, который возвращает сразу
вызываемая функция (IIFE). Всё, что объявлено внутри функции, снаружи не
видно; наружу выходит только то, что функция возвращает, — аналог `export`.
Другие файлы обращаются к нему через имя модуля, например
`model.createEmptySheet()`, — аналог `import`.

### Хранение — `localStorage`

Состояние листа автоматически сохраняется в `localStorage` при каждом
изменении и восстанавливается при загрузке страницы. Данные хранятся одним
JSON-объектом под одним ключом; в объекте есть поле версии схемы, чтобы позже
можно было мигрировать данные.

## Отклонённые варианты

- **Поля поверх изображения PDF.** Точнее совпадает с оригиналом, но не
  адаптируется под мобильные, требует ручной подгонки координат и мешает
  развивать логику листа.
- **Всё в одном `index.html`.** Разметка, стили и логика перемешаны, файл
  быстро вырастает до сотен строк, его трудно читать и ревьюить.
- **Файлы в корне репозитория.** Код смешан с документацией и служебными
  файлами.
- **Папка `src/`.** Обычно означает исходники, которые собираются в `dist/`,
  а сборки у нас нет. К тому же `index.html` должен быть в корне: GitHub Pages
  без Actions публикует только корень или `/docs`, а Vite ожидает `index.html`
  в корне.
- **`css/` и `js/` в корне.** Короче, но иконкам пришлось бы заводить ещё одну
  папку верхнего уровня.
- **Один `styles.css`.** Меньше `<link>`, но файл смешивает несвязанные части
  и растёт с каждым блоком; при переходе на React его всё равно пришлось бы
  делить по компонентам.
- **`@import` вместо нескольких `<link>`.** Браузер загружает импортируемые
  файлы по цепочке, а не параллельно.
- **Один `app.js`.** Смешивает модель, хранилище и работу с DOM.
- **ES-модули (`<script type="module">`).** Дали бы настоящие `import`
  и `export`, но не работают при открытии страницы из файловой системы.
- **Функции и константы на верхнем уровне скриптов.** Все они становятся
  глобальными: имена разных файлов могут столкнуться, а по вызову не видно,
  из какого файла функция.

## Точки роста

Не входят в MVP и делаются отдельными решениями по мере необходимости:

1. **Переход на Vite + React + TypeScript** — когда появится заметная логика:
   несколько персонажей, правила игры, броски кубиков, расчёты.
2. **Экспорт и импорт JSON** — перенос персонажа между устройствами и обмен
   листами. Формат файла совпадает со схемой в `localStorage`.
3. **Экспорт в PDF** — печать или сохранение листа, например через
   `@media print`.

## Последствия

- MVP делается быстро и не требует инфраструктуры. Страница открывается
  двойным кликом и публикуется на GitHub Pages из корня без настроек.
- Данные привязаны к одному браузеру на одном устройстве, пока не реализован
  экспорт и импорт JSON. Очистка данных браузера удалит персонажа.
- Страница не содержит графики издателя игры, поэтому её можно публиковать
  без вопросов о правах на изображения.
- Каждый новый CSS- и JS-файл нужно подключить в `index.html` в правильном
  месте. Ошибка в порядке скриптов проявляется как `ReferenceError` при
  загрузке страницы.
- В глобальной области только четыре имени модулей; внутренние функции файлов
  не пересекаются.
- Переход на Vite + React упрощён: файлы из `assets/css` и `assets/js`
  переезжают в `src/`, обёртка IIFE заменяется на `export`, `tokens.css`
  переносится как есть, `index.html` остаётся на месте. Модель и хранилище
  уже отделены от работы с DOM.
