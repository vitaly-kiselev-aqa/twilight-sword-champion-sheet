# ADR-0002: Unit-тесты на Vitest

- **Статус:** предложено
- **Дата:** 2026-11-08

## Контекст

ADR-0001 запрещает сборку и npm-зависимости, а план MVP предполагает только
ручную проверку в браузере. Логика скриптов растёт: хранилище, чтение полей,
связь полей с данными листа. Ручная проверка не ловит регрессии в этой логике.

## Решение

Скрипты из `assets/js` покрываем unit-тестами на Vitest в окружении jsdom.

- Vitest и jsdom — только `devDependencies` в `package.json`. Страница
  по-прежнему не зависит от npm и открывается двойным кликом.
- Тесты пишем на TypeScript. Код страницы остаётся на JavaScript с JSDoc.
- Тесты лежат в `tests/`, по файлу на модуль.
- Vitest сам запускает файлы `.ts`. Отдельная сборка и новые зависимости
  не нужны.
- Скрипты остаются обычными, не ES-модулями. Тестовый загрузчик читает текст
  скрипта и выполняет его. Модули-зависимости передаются по именам, как
  в общей глобальной области браузера.
- Тесты запускаются одной командой локально и в CI.
- Типы тестов проверяет TypeScript по отдельному конфигу `tests/tsconfig.json`.
  В нём есть типы Node, а в конфиге кода страницы их нет. Так код страницы
  не видит глобальные имена Node, например `process`.
- Конфиг тестов подключает скрипты страницы через `allowJs`. Так тесты видят
  типы модулей, описанные в JSDoc.
- Загрузчик возвращает тип конкретного модуля. Поэтому TypeScript замечает
  в тестах вызов несуществующей функции модуля или неверную заглушку.

## Отклонённые варианты

- **Запуск через `npx` без `package.json`,** как раньше Prettier и TypeScript
  в CI. Vitest ищет jsdom и свой конфиг в папке проекта, поэтому без локальной
  установки запуск ненадёжен.
- **Перевод скриптов на ES-модули ради тестов.** Модули не загружаются
  по `file://`.
- **Экспорт для Node в каждом скрипте** через `module.exports`. Добавляет
  в рабочий код ветку, которая нужна только тестам.
- **Тесты на JavaScript с JSDoc,** как код страницы. Тесты не открываются
  в браузере, поэтому ограничение `file://` на них не действует. Типы в JSDoc
  длиннее, чем в TypeScript, особенно у обобщённых функций вроде загрузчика.
- **Перевод на TypeScript и кода страницы.** Браузер не выполняет TypeScript,
  поэтому понадобилась бы сборка. ADR-0001 оставляет это для перехода
  на Vite + React + TypeScript.

## Последствия

- В репозитории появляются `package.json` и `package-lock.json`, для тестов
  нужен `npm install`.
- TypeScript и Prettier тоже в `devDependencies`. Локально и в CI проверки
  идут одними и теми же версиями и одними командами из `scripts`
  в `package.json`. Отдельная команда запускает все проверки сразу.
- Запрет на npm-зависимости из ADR-0001 касается кода страницы, но не
  инструментов разработки.
- В репозитории два языка: код страницы на JavaScript с JSDoc, тесты
  на TypeScript. Правила типизации для каждого описаны в `AGENTS.md`.
- Vitest убирает типы из тестов, но не проверяет их. Ошибки типов находит
  только `npm run typecheck:tests`.
- При переходе на Vite + React + TypeScript тесты переносятся почти без
  изменений: они уже на TypeScript, а загрузчик заменяется обычным `import`.
